# 用户中心登录改造

## 一、概述

目标：

1.  统一用户中心为独立服务，提供登录页，其他产品通过统一用户中心登录
    
2.  KA客户使用 文档中心 时，可以跳转统一用户中心实现鉴权和创建用户
    
3.  文档中心 作为独立站点时，可以通过统一用户中心实现登录
    
4.  统一用户中心提供OIDC 身份源服务，便于文档中心 客户支持平台及其他SaaS产品快速接入
    
5.  中长期： 算账高手，行情高手 通过统一用户中心登录
    

## 二、背景&现状

| 改造项目 | 现状 | 改造目标 | 问题确认 |
| --- | --- | --- | --- |
| KA 跳转SAAS服务 | 1.  必须提前手动在统一控制中心创建 saas 企业账号<br>    <br>2.  saas 账号的关联需要KA客户手动配置<br>    <br>3.  用户账号的创建和行情服务耦合 | KA 用户在任何状态下（有或者没有SAAS账号，SAAS 用户）可以直接跳转到 SAAS 系统<br>1.  自动创建SAAS 企业账号<br>    <br>2.  saas 用户账号的创建不依赖某一服务 | 自动创建 SAAS 企业账号时需要有客户标识<br>需要确认安全风险和业务异常 |
| 用户中心提供 OIDC 服务 | 无 | 任意三方系统可以注册进SAAS用户中心<br>使用用户中心的登录和用户信息服务 |  |
| 登录入口 | 当前的生意和算账登录虽由 gateway 服务承载，但底层又路由到了算账高手做用户账密鉴权 ，逻辑混乱 | 账密鉴权统一在用户中心维护 |  |

| token 获取 | 鉴权code | id\_token<br>access\_token |  |

ka 跳转到 saas 的账号是什么状态，是否可以账密登录

nginx 转发请求到用户中心统一登录，usercenter 写自己redis, 设置子域名token, 算账拿到 cookie 发现自己redis 没有，到usercenter 查询并设置进自己redis. 退出时先到用户中心退出，然后把自己 redis 内的缓存失效掉
